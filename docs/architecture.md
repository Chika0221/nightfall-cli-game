# 実装構成

## Linux側

- `nightfall/content.py`：シナリオ版2。初期ファイル、参照番号別の記録、保管庫、回収資料、送信後の受領票を決定的に生成する。判定原本は管理パッケージ内だけに置く。
- `nightfall/scenario.json`：調査状況に応じた3段階ヒント。通常画面には問題文・物語の解説を表示しない。
- `nightfall/engine.py`：記録照会、認証、回収、二種類の送信、保存・復旧。資料は参照番号で取得でき、認証後の私信・端末原簿・家族記録などは順不同で探索できる。
- `nightfall/fs.py`：dir_fdとO_NOFOLLOWを使う読み書き。リンクをたどらず、通常ファイルとサイズ上限を検証する。
- `nightfall/daemon.py`：Unixソケットの単一ライター。SO_PEERCREDでcontractorまたはrootの接続だけを受け付ける。
- `nightfall/client.py`：公開クライアント。参照番号や認証情報を固定APIに渡す。パスワード入力はgetpassを使い、エコー入力にフォールバックしない。
- `nightfall/admin.py`：運営用復旧と練習環境の初期化。変更時には管理サービスを停止して排他ロックを取る。

実行時の依存はPython標準ライブラリだけ。管理コードはrootだけが読める `/opt/nightfall` のvenvへ、公開クライアントは別に配置する。開発パッケージをプレイヤーのPythonパスに置かない。

## 進捗と復旧

SQLiteにシナリオ版、取得参照番号、認証・回収・送信状態、経過時間、ヒント履歴、未完了操作、保存地点のファイルスナップショットを保存する。版1のデータは変更せず、明示的なエラーで停止する。移行には新しい専用環境を用意する。

記録取得・認証・回収・送信・復旧は、未完了操作を先に永続化する。ファイル処理とスナップショット作成後に状態を確定する。中断時は次の要求やサービス再起動で同じ操作を再実行する。取得済み記録への再照会や送信の再実行は進捗を重複させない。

内部の保存地点番号は1〜10。資料取得の順序は固定せず、最初の7操作（6資料＋archive認証）で最大8、回収で9、協力者報告の受付で10となる。任意の未取得資料は回収後も取得できる。core認証や遅れて取得した資料は同じ保存地点のスナップショットを更新する。

`mission reset` と運営復旧は `/home/contractor` と `/srv/nightfall` を最後に成功した操作直後の状態へ戻す。範囲を表示し、確認後に実行する。取得済み記録と認証状態は取り消さない。core認証後の復旧ではcore資料も戻る。後から行った編集は失われる。公開資料の原本は管理側データから再配置するため、古い資料への誤編集が後の保存地点へ混入していても復旧できる。

入力プロンプトには内部の保存地点番号を付け、別端末で接続状態が変わった場合に古い入力を拒否する。公開画面には問題番号・正解・真相の解説を表示しない。

累計時間は起動シェルの開始・終了通知の間だけ加算する。PIDとプロセス開始時刻を管理側で確認し、終了通知が失われてもプロセス消滅を検出する。120分は目安であり、時間切れによる失敗はない。物語内の時刻はファイルに固定され、実時間で人物が死亡することはない。

## 送信物

`mission check` は協力者報告、`mission submit` は最終移送資料を検証する。外部通信は行わない。協力者報告には偽の集合場所だけを含め、機密指令や個人情報を混ぜると拒否する。最終移送資料には機密原本5点・manifest・乗員名簿・空のREADYを含める。

圧縮後1 MiB、解凍ストリーム全体8 MiB、100エントリに制限する。tarをファイルシステムに展開せず、通常ファイルの内容をメモリで検証する。絶対パス、親ディレクトリ参照、リンク、特殊ファイル、疎ファイル、重複パス、余分な構成は拒否する。

機密原本は管理側の不変データとバイト比較する。manifestはCRLFをLFに正規化し、順序不問、重複不可。設定・名簿はキー順を含めて検証し、CRLFと末尾改行の有無を許容する。プレイヤー領域の原本の残存・内容、READY、キャッシュ容量も検証する。

## Windows側

PowerShellがWSLの検出・インポート・起動・独立した練習環境の作成を担当する。バイナリtarの入力には.NETのStreamを使う。

`mission replay N` は保存地点番号を管理領域へ記録する。Windows側がシェル終了後にroot用固定コマンドで回収し、配布rootfsから練習環境を作る。練習では標準の調査順で地点Nを再現するため、本編で別の順序で集めた資料の配置とは異なる場合がある。本編の状態は変更しない。
